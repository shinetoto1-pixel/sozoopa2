# 1단계: 뉴스 수집 — 원칙 문서

> sozoopa 프로젝트의 `scripts/news_monitoring_priority.md`에서 수집 절차만 뽑아 간소화한 문서(2026-07-31).
> 이 문서는 오직 "뉴스를 모아서 헤드라인 스크리닝(1차·2차)까지 끝낸다"까지만 다룬다. 본문 확보는
> 2026-08-03부로 2단계(`판단실행.ps1`)로 넘어갔다 — 테마별 대표 뉴스 1건만 WebFetch로 확보하는
> 방식으로 바뀌었고, 이 프로젝트의 1단계는 더 이상 본문을 확보하지도 `수집로그.md`를 만들지도 않는다.

## 수집 범위 정하기

수집은 한 번에 끝낼 필요 없이 필요할 때마다 여러 번 나눠 실행할 수 있다(예: 저녁·자정·새벽 각각 한 번씩).
매번 "지난번에 어디까지 모았는지 확인하고, 거기서부터 지금까지 새로 나온 만큼만 이어서 모은다"는 동일한
절차를 반복하는 것뿐이다.

**전체 시간창은 전일 18:00 ~ 당일 07:30.** 다음뉴스 기사 URL(`v.daum.net/v/YYYYMMDDHHMMSSmmm`)에
발행시각(KST)이 인코딩돼 있어 이걸로 정확히 필터링한다(목록의 "N분 전" 상대시간은 참고용일 뿐, 판단은 URL
타임스탬프 기준).

실행할 때마다:

1. **폴더 날짜 결정**: 트리거 시각 기준 **다음 개장일**을 계산해 `daily/YYYYMMDD/` 폴더로 삼는다(예: 화요일
   밤 10시 → 수요일 폴더, 수요일 새벽 1시 → 수요일 폴더, 토요일 아무 때나 → 월요일 폴더 — 요일과 무관하게
   항상 다음 개장일로 계산하므로 주말에 미리 모아두는 것도 정상 동작이다). 음력 공휴일·대체공휴일·임시공휴일
   등으로 다음 개장일이 불확실하면 확신 없이 진행하지 말고 사용자에게 먼저 확인한다.
2. **시작점 결정**: 그 폴더에 `수집URL.md`가 이미 있으면, 거기 있는 URL과 마주치는 지점까지만 이어서
   수집한다(최신순 정렬이므로 그 지점부터는 이미 확보된 것). 없으면 18:00부터 시작한다 — 단, 이미 05:00를
   넘긴 시점이라 18:00부터 다시 훑기엔 시간이 부족하면 05:00부터 시작한다(관측상 이 구간에 뉴스가 가장
   몰려서 이것만으로도 충분).
3. **끝점**: 트리거 시각과 07:30 중 더 이른 쪽까지. 아래 "수집 실행" 절차를 그 범위만큼 수행하고 끝낸다.

## 수집 실행

### 대상 섹션

다음뉴스(news.daum.net) 사용 — 네이버뉴스는 접속 차단됨. 아래 URL로 각 하위 카테고리에 직접 들어간다(경제홈
등 상위 페이지는 미리보기만 나오므로 반드시 하위 카테고리 URL로 이동).

우선순위(2026-08-02 사용자 지정, 사용량 제약으로 일부만 처리할 때 이 순서대로):
- 1순위: 경제정책(news.daum.net/policy) / 산업(news.daum.net/industry) / 국제경제(news.daum.net/worldeconomy)
- 2순위: 외교국방(news.daum.net/dipdefen) / 테크(news.daum.net/technology) / 재난안전(news.daum.net/safety) /
  주식(news.daum.net/stock)
- 3순위: 벤처스타트업(news.daum.net/startup) / 의료보건(news.daum.net/medical) / AI(news.daum.net/ai-tech) /
  IT기업(news.daum.net/it-tech)

시간창 안의 URL은 전부(헤드라인만 보고도) 수집한다 — 이 단계에서 거르지 않는다. 뭘 본문까지 확보할지는
아래 "헤드라인 스크리닝"(1차·2차) 몫이다(2026-08-02 추가 — 뉴스량이 예상보다 많아서 본문확보 전수 처리가
사용량 부담이 커진 것을 계기로 도입).

### 실행 순서 — URL수집 → 헤드라인 1차 스크리닝 → 헤드라인 2차 스크리닝

1. **URL 수집**: 위 섹션을 순회하며 URL과 헤드라인만 먼저 모은다. 이 단계에서는 본문을 열지 않는다.
2. **헤드라인 1차 스크리닝**: 모인 헤드라인만 보고 "본문까지 확보할 가치가 있는가"를 느슨하게(recall 우선)
   거른다. 기준은 아래 "헤드라인 1차 스크리닝" 참고.
3. **헤드라인 2차 스크리닝**: 1차 통과분이 여전히 많아서(2026-08-02 실측 597건 중 336건), 정교한 기준으로
   한 번 더 거른다. 기준은 [2차스크리닝기준.md](2차스크리닝기준.md) 참고 — 판정은 통과/경제이슈참고/기각
   삼분류. 이 단계도 헤드라인만으로 판정하며 본문은 열지 않는다.

1단계는 여기서 끝난다. 본문 확보(테마당 대표 뉴스 1건만 WebFetch)는 2단계
`판단실행.ps1`이 `2차헤드라인스크리닝.md`를 입력으로 받아서 처리한다(2026-08-03 개편).

**URL 수집**: 섹션별로 URL을 최신순으로 `수집URL.md`에 저장하고, "새로운뉴스" 버튼을 눌러 시간창 경계에
닿을 때까지 계속 불러온다(묶음 수·건수 상한 없음). 경계 밖으로 나가면 멈춘다. 예외 없이 전부 수집
대상에 넣는다 — 뭘 빼고 넣을지 고르는 건 판단이라 2단계 몫이다.

**URL 수집 스크립트** (브라우저에서 실행, 한 번의 JS 호출로 클릭+추출 반복):

```javascript
(async function(){
  const box = document.querySelector('.box_news_headline2');
  const getBtn = () => Array.from(box.querySelectorAll('a,button'))
    .find(e => e.textContent.trim() === '새로운뉴스' || e.textContent.trim() === '새로운 뉴스');
  const getLinks = () => Array.from(box.querySelectorAll('a[href*="v.daum.net"]')).map(a => a.href);
  const wait = (ms) => new Promise(r => setTimeout(r, ms));

  const boundary = new Date("2026-07-31T18:00:00+09:00");  // 실행 전 실제 경계 시각으로 교체
  const knownUrls = new Set([]);  // 이어붙이기 상황에서만: 이미 수집URL.md에 있는 URL

  const parseTs = (url) => {
    const m = url.match(/\/v\/(\d{14})/);
    if (!m) return null;
    const s = m[1];
    return new Date(`${s.slice(0,4)}-${s.slice(4,6)}-${s.slice(6,8)}T${s.slice(8,10)}:${s.slice(10,12)}:${s.slice(12,14)}+09:00`);
  };

  const batches = [];
  let prevLinks = null;
  let firstOldest = null;
  for (let i = 0; i < 15; i++) {
    const links = getLinks();
    if (prevLinks && JSON.stringify(links) === JSON.stringify(prevLinks)) break;
    if (knownUrls.size && links.some(u => knownUrls.has(u))) { batches.push(links); break; }
    const oldest = links[links.length - 1];
    const ts = oldest ? parseTs(oldest) : null;
    if (i === 0) { firstOldest = ts; }
    else if (ts && firstOldest && ts > firstOldest) { break; }  // wrap-around: 더 과거로 못 감, 여기서 포기
    batches.push(links);
    prevLinks = links;
    if (ts && ts <= boundary) break;
    const btn = getBtn();
    if (!btn) break;
    btn.click();
    await wait(700);  // 클릭 직후 바로 읽으면 직전 묶음과 동일 내용이 반환되므로 필수 대기
  }
  return {boundary: boundary.toISOString(), batches};
})();
```

"새로운뉴스"는 약 5번 클릭(약 75건)이 한계다 — 그 이상은 최신 목록으로 되돌아간다(위 스크립트가 자동 감지
후 중단). 경계까지 못 미치면 그 구간은 포기하고 다음 섹션으로 진행한다.

URL을 확보하면 **읽기 시작하기 전에** 바로 `daily/YYYYMMDD/수집URL.md`에 헤드라인과 함께 체크리스트로
저장한다(헤드라인은 목록 페이지에서 URL과 같이 뽑은 것 — 1차 스크리닝에 씀):

```
## 경제정책 (89건)
- [ ] 헤드라인 텍스트 | https://v.daum.net/v/20260730072425668
...
```

헤드라인 스크리닝을 거치면 같은 줄에 결과가 세 번째 칸으로 붙는다:

```
- [ ] 헤드라인 텍스트 | https://v.daum.net/v/20260730072425668 | 통과(신선도)
- [ ] 헤드라인 텍스트 | https://v.daum.net/v/20260730072425669 | 기각(노이즈컷-부고)
- [ ] 헤드라인 텍스트 | https://v.daum.net/v/20260730072425670 | 중복(대표: https://v.daum.net/v/20260730072425668)
```

(체크박스는 본문확보가 1단계 안에 있던 시절 "본문확보 여부" 표시로 쓰였던 흔적이다 — 2026-08-03
개편 이후 1단계는 본문을 확보하지 않으므로 지금은 항상 `[ ]`로 남는다.)

## 헤드라인 1차 스크리닝

세 개 AI에게 "오늘의 주도테마 선정 전략"을 물어보고 답을 종합해서 만든 기준(2026-08-02). 헤드라인만
보고 판단하는 **느슨한(recall 우선) 필터**다 — 애매하면 통과시켜서 본문에서 다시 보게 한다. 여기서
기각되는 건 "명백히 볼 가치 없는 것"뿐이고, 정교한 테마 판단(신선도 vs 빈도수, 단기촉매 등)은 여전히
2단계 몫이다.

### 메인 전략 (셋 중 하나라도 걸리면 통과)

- **명백한 촉발요인**: "발표·체결·승인·경신·발령·확대" 등 오늘 새로 일어난 일임을 시사하는 구체적 동사가
  헤드라인에 있는가
- **해외동조화**: 해외(미국·중국 등) 시장·기업 관련 헤드라인이고 국내 관련 섹션과 연결될 소지가 있는가
- **신선도**: 헤드라인이 기존에 못 보던 새로운 키워드·소재를 담고 있는가

### 보조 축 — 재료중심분류

산업명이 아니라 "왜 움직이는가"로 분류: 정책 / 실적 / 공급망 / 규제 / 사고사건 / 신규기록(최초·역대) /
M&A / 기타. 어느 카테고리에도 안 걸리면 통과 근거가 약하다는 신호.

### 뒷받침 증빙

금액 언급(수천억~조 단위, 달러 환산 시에도 상당 규모) + 투자·제재 키워드가 있으면 위 전략 판단을 보강.

### 노이즈컷 (즉시 기각)

부고·인사동정, 단순 목표가 조정, 순수 시황 해설·칼럼 — 헤드라인만 봐도 명백한 것만 해당. 애매하면
기각하지 말고 통과시킨다(recall 우선 원칙).

### 중복 처리

- **같은 섹션 안 중복**(같은 사건을 여러 매체가 각자 기사화, 예: SRT 관련 기사 다수): 사실관계가 거의
  동일할 가능성이 높으므로 **대표 1건만 통과**시키고 나머지는 `중복(대표: URL)`로 표시. 대표는 헤드라인에
  구체적 수치·고유명사가 더 많거나 더 최신인 쪽.
- **여러 섹션에 걸친 중복**(예: 경제정책과 산업에 같은 사건): 다른 각도(정책 영향 vs 산업 파급)일 수 있으므로
  병합하지 않는다. 둘 다 통과 여부를 각자 판단하되, 관련이 있다는 사실만 사유에 덧붙인다.

### 아직 못 하는 것 (제약 때문에 안 함)

- 매체 수·언급 빈도로 판정(2단계 원칙의 "빈도수는 착시" 원칙과 충돌 — 교차확인 참고용으로만 언급 가능,
  선정/기각 기준으로 쓰지 않는다)
- 수급·거래량 교차확인(장 시작 전이라 데이터 자체가 없음)
- 과거 유사 뉴스 → 대장주 매핑 이력 대조(데이터 축적 전 — `../사후검증/1차스크리닝전략_설계.md` 참고)

## 헤드라인 2차 스크리닝

1차를 통과한 것 중 "진짜 테마 후보 자격이 있는가"를 정교하게 가리는 단계. 기준 전체는
[2차스크리닝기준.md](2차스크리닝기준.md) 참고.

**경제이슈참고 기록은 경제정책·국제경제 섹션만**(2026-08-04) — 판정 자체는 모든 섹션에서 동일한
기준으로 하되, 다른 섹션에서 나온 경제이슈참고 판정까지 전부 기록하면 비효율적이라 `경제이슈참고.md`에는
이 두 섹션 것만 남긴다(그 외 섹션의 경제이슈참고 판정은 기각과 동일하게 버려짐).

2차 스크리닝도 1차와 마찬가지로 헤드라인만 보고 판정하며 본문은 열지 않는다. 본문 확보는 2단계
`판단실행.ps1`이 담당한다(테마당 대표 뉴스 1건만 WebFetch, 개별주이슈·경제이슈참고는 본문 확보 안 함 —
[CLAUDE.md](../CLAUDE.md)의 "2단계 독립 실행" 참고).

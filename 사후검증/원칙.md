# 사후검증 — 원칙 문서 (미설계, 확인 필요)

## 이 프로세스가 하는 일

작성된 포스팅(과 그 근거가 된 판단)을 나중에 취합해서, 실제로 맞았는지 검증하고 판단 로직을 개선한다.
1·2·3단계(수집→판단→포스팅) 파이프라인과는 무관하게 **독립적으로 실행**한다(2026-07-31 결정 — 사용자가
"작성된 글을 취합해서 검증하고 개선하는 건 1,2,3단계와 관계없이 별도의 프로세스로 하는 게 좋겠다"고 정리).

## 지금 있는 것

- `테마검증로그.md`: 전 거래일 실제 주도테마(alphasquare 급상승테마 기준)를 날짜별로 쌓아두는 원재료.
  원래 2단계 문서의 "사전 준비" 단계였던 걸 그대로 옮겨옴.

## 아직 설계 안 된 것

- 이 프로세스를 **언제** 실행하는지(예: 매일? 주간? 판단로그 몇 개 쌓였을 때?)
- **어떻게** 검증하는지(테마검증로그.md와 각 날짜 판단로그.html을 어떤 절차로 대조하는지)
- 검증 결과를 어디에 어떤 형식으로 남기고, 그걸 2단계의 판단 기준(`../2단계_판단/원칙.md`)에 어떻게
  피드백할지 — 수동으로 문서를 고칠지, 아니면 다른 방식인지

임의로 절차를 만들어 넣지 않는다. 사용자와 상의해서 구체화한다.

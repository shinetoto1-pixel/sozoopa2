# 3단계: 포스팅 작성 — 원칙 문서 (일부 미완성, 확인 필요)

## 프로젝트 목적 (2026-07-27 사용자 피드백 반영, 원래 1단계 문서 서두에 있던 걸 여기로 이관 2026-07-31)

이 프로젝트(수집·판단·포스팅 전체)를 관통하는 최상위 목적은 **블로그에 사람이 많이 들어오게 해서 수익
파이프라인을 만드는 것**이다. 아래 우선순위로 이해한다:

1. **최상위 목적 — 트래픽·수익화**: 방문자·구독자 증가와 그로 인한 블로그 수익 창출이 최우선 지표다.
2. **수단 — 양질의 정보 생산**: 트래픽을 만들려면 정확한 테마 예측과 신뢰할 수 있는 컨텐츠를 꾸준히 생산해야
   한다. 1단계(수집)·2단계(판단) 절차, 그리고 2단계의 "오늘 오를 테마를 찾는다"는 대전제는 전부 이
   "양질의 정보"를 만들기 위한 하위 수단이다.
3. **부수 효과 — 개인 매매 활용**: 이 과정에서 도출한 테마 판단은 부수적으로 본인의 매매 근거·차익 실현에도
   쓰인다.

**우선순위 원칙**: 세 목표가 충돌할 때는 위 순서(트래픽·수익화 > 정보 품질 > 개인 매매 활용)를 따른다. 예를
들어 "정확도는 높지만 읽기 딱딱한 글"과 "정확도는 비슷하되 독자 유입·가독성에 더 도움되는 구성" 중 골라야
한다면 후자 쪽으로 기울어도 된다 — 최종 목적은 트래픽이지 예측 정확도 그 자체가 아니다.

**문체·이미지·포스팅 빈도·SEO 등 이 문서가 아직 다루지 않는 결정들도 "이게 독자 유입·리텐션에 도움이
되는가"를 1차 기준으로 판단한다.**

## 지금은 단계별 개별 실행 (2026-07-31)

아직 각 단계가 다듬어지는 중이라, 당분간 1·2·3단계를 자동으로 이어붙이지 않고 **매번 사용자가 어느 단계를
실행할지 직접 지시**한다(예: "1단계 수집 시작하자", "2단계 판단하자", "포스팅 초안 쓰자" 등 단계별 명령).
"포스팅 작성하자" 한마디로 1→2→3단계가 자동으로 이어지는 일괄 실행은 아직 없다 — 사용자가 "이제 일괄
실행해도 되겠다"고 판단하면 그때 별도로 일괄 실행 명령을 만든다.

## 입력

2단계의 산출물만 사용한다 — 원본 `수집로그.md`나 1단계 단계를 다시 참조하지 않는다.

- `../daily/YYYYMMDD/판단로그.html` (선정된 테마·근거·매핑 종목·개별주 이슈 후보)

차트·시장지표·메인이미지는 판단로그를 바탕으로 **이 단계에서 직접 생성**한다(아래 "이미지 생성" 참고) —
2단계는 종목을 매핑하는 데까지만 하고, 실제 이미지 파일을 만드는 건 초안 조립 작업이라 3단계 몫이다.

## 이미지 생성

스크립트는 `scripts/`, PPT 템플릿은 `assets/`에 있다.

**개별 종목 차트 — `make_chart.py`** (다음금융 API 기반, 당일 종가까지 항상 정확히 반영):
- 사용법: `python scripts/make_chart.py {6자리 종목코드} {종목명} [봉개수(기본 100)]`. 실제 포스팅용으로
  만들 때는 `make_chart(code, name, count=100, out_path="../daily/YYYYMMDD/이미지/0N_종목명.png")`처럼
  최종 경로를 `out_path`에 바로 지정한다(생성 후 옮기는 2단계 과정이 아니라 처음부터 최종 위치에 저장).
  번호(0N)는 그날 초안 구성 순서(테마 순서대로, 개별 종목 이슈는 그 뒤)에 맞춰 직접 정한다.
- 디자인: 캔들(상승 빨강·하락 파랑) + 이동평균선 4개(5일 초록·20일 주황·60일 보라·120일 금색, 옅은 배경
  범례) + 거래량(초록 단색, 테두리 없음). 캔들·거래량 패널 사이 구분선은 진하게. x축은 "03.05" 형식 숫자
  날짜(맨 오른쪽 봉에도 날짜 강제 표기). y축은 오른쪽 배치, 지수표기 없이 숫자 그대로. 오늘 종가는 점선+
  별도 눈금으로 강조. "Price"/"Volume" 축 제목은 생략. 제목엔 봉 개수를 넣지 않는다(예: "SK하이닉스
  (000660)"만).
- 이 규칙은 시세 데이터가 들어가는 차트에만 적용된다 — `00_메인이미지`(`make_main_image.ps1`)는 시세
  데이터가 없는 배너라 대상이 아니다. `이미지/` 폴더를 정리할 때 시세 차트 파일만 콕 집어 지운다(폴더
  전체를 밀면 메인이미지도 같이 지워짐).

**시장지표 — `make_market_summary.py`** (다음뉴스 금융지표 기반):
1. 브라우저로 `news.daum.net/finance` 접속 → 금융지표 위젯(증시/환율/금리/원자재 탭) 4개를 각각 클릭해
   수치 추출.
2. `scripts/market_data.json`에 스키마대로 저장(각 항목 name·date·value·change·pct·unit).
3. `build_market_summary(data, out_path="../daily/YYYYMMDD/이미지/01_시장지표.png")`처럼 최종 경로를
   바로 지정해 실행.
- 디자인: 세로로 4개 대분류(증시→환율→금리→원자재 순), 각 패널은 전체 폭을 쓰고 대분류별 원래 열 개수
  (증시 4·환율 3·금리 3·원자재 4) 유지. 상승 빨강·하락 파랑, 대분류 제목 위 얇은 색상 액센트 바(글씨와
  겹치지 않게), 카드 가로폭은 좁게(`FIG_W=9.6`) 유지.

**이미지 번호**: `00_메인이미지` → `01_시장지표` → `02~` 개별 종목(테마 순서대로) → 개별주 이슈.

## 개별주 이슈 배치

2단계가 판단로그에 남긴 개별주 이슈 후보를, 테마 섹션들 다음에 초안 맨 뒤에 짧게 모아 소개한다. 호재든
악재든 가리지 않고 "이런 뉴스가 있었다" 수준으로 한두 문장씩만 — 매수/매도 방향은 판단하지 않는다. 종목당
필요하면 차트를 하나씩 붙인다(위 "이미지 생성" 규칙 동일 적용). 테마 섹션과 마찬가지로 근거 기사 링크를
반드시 넣는다(원 언론사 링크 우선, 안 되면 다음뉴스 폴백).

sozoopa 프로젝트를 확인한 결과, 1단계 문서처럼 문체·톤앤매너를 명문화한 문서는 초안 작성 단계에 없었다.
지금까지는 매일 그때그때 사용자 피드백을 받으며 대화형으로 작성돼 온 것으로 보인다.

**다음에 할 일**: sozoopa의 기존 `초안.html` 몇 개(예: `일별작업/20260729/초안.html`, `20260730/초안.html`)를
스타일 템플릿으로 참고해서, 이 문서에 실제 구성 규칙(섹션 순서, 문체, 링크 표기 방식 등)을 정리해야 한다.
사용자와 상의 후 채울 것 — 임의로 규칙을 만들어 넣지 않는다.

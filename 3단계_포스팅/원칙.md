# 3단계: 포스팅 작성 — 원칙 문서

> 2026-08-03 — 입력을 2단계 개편(헤드라인 먼저 판단 후 선정분만 본문확보)에 맞춰 갱신하고, 문체·구성
> 원칙을 처음으로 채워넣었다(과거작성글·초안/본안 비교로 학습, 아래 "문체" 참고).

## 프로젝트 목적

이 프로젝트(수집·판단·포스팅 전체)를 관통하는 최상위 목적은 **블로그에 사람이 많이 들어오게 해서 수익
파이프라인을 만드는 것**이다.

1. **최상위 목적 — 트래픽·수익화**: 방문자·구독자 증가와 그로 인한 블로그 수익 창출이 최우선 지표다.
2. **수단 — 양질의 정보 생산**: 1·2단계 절차 전체가 이 "양질의 정보"를 만들기 위한 하위 수단이다.
3. **부수 효과 — 개인 매매 활용**: 도출한 테마 판단은 부수적으로 본인의 매매 근거에도 쓰인다.

세 목표가 충돌하면 위 순서를 따른다 — 정확도보다 독자 유입·가독성이 우선일 수 있다.

## 입력

2단계의 산출물만 쓴다 — 원본 헤드라인·수집 자료를 다시 참조하지 않는다.

- `../daily/YYYYMMDD/포스팅작성뉴스및종목.md` — 실제 글감(경제이슈참고 링크, 선정 테마별 본문요약+
  관련종목, 개별주 이슈)
- `../daily/YYYYMMDD/판단로그.md` — 선정 근거가 더 필요하면 참고(주 자료는 아님)

차트·시장지표·메인이미지는 이 자료를 바탕으로 **이 단계에서 직접 생성**한다(아래 "이미지 생성" 참고).

## 산출물 — 두 가지 문체

같은 날 뉴스로 **성격이 다른 글 두 개**를 만든다. 톤을 섞지 않는다.

### 1. 메인 블로그용 (`초안.html`, `본안.txt`)

캐주얼한 1인칭 개인 투자자 목소리. 과거 글(`../참고자료 과거작성글, 7월말 초안본안/`)에서 확인한 특징:

- **어투**: 존댓말이되 구어체("~하네요", "~인듯합니다", "차트는..?"). 감탄사·이모티콘성 표현(ㅋㅋ, ㅜㅜ,
  ;;)을 자연스럽게 섞는다. 딱딱한 애널리스트 톤 금지.
- **불확실성을 숨기지 않는다**: "이게 호재일런지..?", "저게 물량정리인지 매집인지는 나중에 봐야
  알겠죠" 처럼 판단이 애매하면 애매하다고 그대로 쓴다. 확신에 찬 단정적 문장으로 바꾸지 않는다.
  개별주 이슈는 원래 원칙대로 매수/매도 방향을 판단하지 않는다.
- **모든 종목에 코멘트를 억지로 달지 않는다**: 특별히 할 말 없으면 종목명만 쓰고 넘어가거나
  "그놈이 그놈"처럼 짧게 넘어간다. 코멘트 길이를 균등하게 맞추려 하지 않는다.
  가장 먼저 언급하는 테마·종목에 더 공들이고, 뒤로 갈수록 짧아지는 것도 자연스럽다.
- **개인 매매 성향을 노출한다**: "저는 이번주에 매수가 꽤 있었습니다", "저도 좀 샀고, 오늘도 좀
  살겁니다"처럼 자기 행동을 공유하는 문장을 글 끝에 자연스럽게 넣는다.
- **차트를 하나의 캐릭터처럼 다룬다**: "차트 처참하네요", "저 아랫단에서 거래량을 터트리면서 하단선을
  지지해준 형상입니다" 같은 식으로 차트 모양 자체에 대한 즉흥적 반응을 남긴다.
- **제목**: `YYYY년 MM월 DD일 장전뉴스 주식뉴스 오늘 이슈 시황 (짧은 키워드 나열)`. 괄호 안은
  간결하게(선정 테마 이름 위주, 수식어 과하게 안 붙임).
- **본문 구성 순서**:
  1. 요일 인사 + 어제 시황 캐주얼 요약(메인이미지) — 이때 `포스팅작성뉴스및종목.md`의 "경제이슈참고"
     항목들(최대 3건)을 이 인사말에 자연스럽게 녹이고, **근거 뉴스링크(`.newslink` 박스)도 반드시
     같이 넣는다**(2026-08-03 — 문장으로만 녹이고 링크를 빠뜨린 적 있음, 반드시 확인).
  2. 시장지표 이미지
  3. 오늘 전체적으로 어떤 관점으로 볼지 한두 문장(테마가 약한 날은 "오늘은 뉴스가 볼 게 별로
     없었다"고 솔직히 써도 됨)
  4. 테마별 섹션(`#테마명` 표시) — 대표 뉴스 제목+링크+해시태그 → 이 테마를 고른 이유(캐주얼하게)
     → 테마 안 종목별로 차트+짧은 코멘트(위 원칙대로 억지로 채우지 않음)
  5. `#개별주이슈` 섹션 — "테마로 묶기엔 애매하지만 눈에 띈 것들" 톤으로 소개, 종목당 차트+짧은 코멘트
  6. 마무리 — 오늘 하루 총평 + (있으면) 본인 매매 언급 + 화이팅 인사
- **링크**: 원 언론사 링크 우선(예: `n.news.naver.com`, 언론사 자체 도메인), 안 되면 다음뉴스 폴백.
  뉴스 제목 밑에 해시태그(#테마 #종목명들)를 붙이는 관례를 따른다.
- **해시태그 중복 금지**(2026-08-07): `<hr>` 직후 테마 소개용 태그 줄은 `#테마명`만 짧게(서브테마
  있으면 `#서브테마`까지만) — 종목명은 넣지 않는다. 종목명이 다 들어간 전체 태그(`#테마 #종목명들`)는
  `.newslink` 박스 안에만 한 번 쓴다. 두 곳에 똑같은 태그 목록을 반복해서 넣지 않는다.

### 2. 구글블로그용 (`초안_구글블로그.html`, 메인 블로그와 같은 `daily/YYYYMMDD/` 폴더에 — 별도 하위폴더 안 만듦)

**메인 블로그와 톤이 완전히 다르다** — 격식있는 애널리스트/기사체. 1인칭·유머·개인 매매 언급 없음.

- **어투**: 객관적 서술체("~했다", "~로 집계됐다", "~로 풀이된다"), 3인칭 관찰자 시점.
- **구성**: 리드 문단에 경제이슈참고를 녹이고(아래 참고), 그 다음 `<h2>` 번호 매긴 테마 섹션(예: "1. 지수
  및 전일 시황 개관", "2. 급락 배경 — 반도체가 낙폭의 80%") — 마치 증권사 리포트나 경제기사처럼 구조화.
  경제이슈참고 3건은 리드 문단 서술 + 번호 없는 `<h2>참고 — 주요 경제 이슈</h2>` 섹션에 `.newslink`
  박스로 넣는다(메인 블로그와 마찬가지로 링크 빠뜨리지 않도록 확인).
- **근거 밀도**: 메인 블로그보다 수치·출처 인용이 더 촘촘하다(예: "메리츠증권 분석에 따르면",
  구체적 %·포인트·순매수액 등을 문장 안에 정확히 명시).
- **제목**: `YYYY년 M월 D일 국내외 증시 동향 및 주요 이슈 분석 — (부제)` 형식.
- 첫 문단에 오늘 다룰 내용 전체를 요약하는 리드 문단을 둔다(신문 기사 리드 문단 방식).
- **뉴스링크와 차트 자리는 메인 블로그와 똑같이 필수다** — 톤만 다르지 자료(`.newslink` 박스로 원문
  제목+링크, 종목마다 `.photo` 차트 placeholder)는 똑같이 다 넣는다. 문체가 격식있다고 이걸 생략하는
  실수를 하지 않는다(2026-08-03 — 초안 작성 중 이걸 빠뜨린 적 있음, 반드시 확인).

두 글 다 같은 선정 테마·종목·근거를 다루지만, 문장을 처음부터 각 톤에 맞게 다시 쓴다(한쪽을 기계적으로
번역/변환하지 않는다).

## 이미지 생성

스크립트는 `scripts/`, PPT 템플릿은 `assets/`에 있다.

**개별 종목 차트 — `make_chart.py`** (다음금융 API 기반, 당일 종가까지 항상 정확히 반영):
- 사용법: `python scripts/make_chart.py {6자리 종목코드} {종목명} [봉개수(기본 100)]`. 실제 포스팅용으로
  만들 때는 `make_chart(code, name, count=100, out_path="../daily/YYYYMMDD/이미지/0N_종목명.png")`처럼
  최종 경로를 `out_path`에 바로 지정한다(생성 후 옮기는 2단계 과정이 아니라 처음부터 최종 위치에 저장).
  번호(0N)는 그날 초안 구성 순서(테마 순서대로, 개별 종목 이슈는 그 뒤)에 맞춰 직접 정한다.
- 디자인: 캔들(상승 빨강·하락 파랑) + 이동평균선 4개(5일 초록·20일 주황·60일 보라·120일 금색, 옅은 배경
  범례) + 거래량(초록 단색, 테두리 없음). 캔들·거래량 패널 사이 구분선은 진하게. x축은 "03.05" 형식 숫자
  날짜(맨 오른쪽 봉에도 날짜 강제 표기). y축은 오른쪽 배치, 지수표기 없이 숫자 그대로. 오늘 종가는 점선+
  별도 눈금으로 강조. "Price"/"Volume" 축 제목은 생략. 제목엔 봉 개수를 넣지 않는다(예: "SK하이닉스
  (000660)"만).
- 이 규칙은 시세 데이터가 들어가는 차트에만 적용된다 — `00_메인이미지`(`make_main_image.ps1`)는 시세
  데이터가 없는 배너라 대상이 아니다. `이미지/` 폴더를 정리할 때 시세 차트 파일만 콕 집어 지운다(폴더
  전체를 밀면 메인이미지도 같이 지워짐).

**시장지표 — `make_market_summary.py`** (다음뉴스 금융지표 기반):
1. 브라우저로 `news.daum.net/finance` 접속 → 금융지표 위젯(증시/환율/금리/원자재 탭) 4개를 각각 클릭해
   수치 추출.
2. `scripts/market_data.json`에 스키마대로 저장(각 항목 name·date·value·change·pct·unit).
3. `build_market_summary(data, out_path="../daily/YYYYMMDD/이미지/01_시장지표.png")`처럼 최종 경로를
   바로 지정해 실행.
- 디자인: 세로로 4개 대분류(증시→환율→금리→원자재 순), 각 패널은 전체 폭을 쓰고 대분류별 원래 열 개수
  (증시 4·환율 3·금리 3·원자재 4) 유지. 상승 빨강·하락 파랑, 대분류 제목 위 얇은 색상 액센트 바(글씨와
  겹치지 않게), 카드 가로폭은 좁게(`FIG_W=9.6`) 유지.

**이미지 번호**: `00_메인이미지` → `01_시장지표` → `02~` 개별 종목(테마 순서대로) → 개별주 이슈.

## 개별주 이슈 배치

2단계가 넘긴 개별주 이슈 후보를, 테마 섹션들 다음에 초안 맨 뒤에 짧게 모아 소개한다. 호재든 악재든
가리지 않고 "이런 뉴스가 있었다" 수준으로 한두 문장씩만 — 매수/매도 방향은 판단하지 않는다. 종목당
필요하면 차트를 하나씩 붙인다(위 "이미지 생성" 규칙 동일 적용). 근거 기사 링크를 반드시 넣는다(원
언론사 링크 우선, 안 되면 다음뉴스 폴백).

## 다음 단계 — 사후검증 트리거

오늘자 초안(과 이미지)까지 다 끝나면, 이어서 직전 영업일 몫의 사후검증을 수행한다(`../사후검증/원칙.md`
참고 — antwinner.com 실측 데이터와 대조). 1·2·3단계와는 무관한 별도 프로세스지만, 트리거 시점만 3단계
완료 직후로 잡는다(그 시점이 직전 영업일 실측 데이터를 구할 수 있는 가장 이른 때라서).
